# Study plan for the next few weeks (plain English)

Goal: be able to explain FDE clearly, answer technical questions, and show you can ship customer outcomes.

## Week 1 — Foundations

**Learn**
- What FDE is
- FDE vs SWE / Solutions Engineer / Support
- Day in the life
- Glossary terms

**Do**
- Read docs 01–05 in this repo
- Write your own 60-second FDE definition from memory
- Practice the presentation talk track once a day

**Done when**
- You can explain FDE without notes in under 2 minutes

## Week 2 — Delivery skills

**Learn**
- Discovery questions
- Scoping a thin vertical slice
- Deployment basics (local → staging → prod idea)
- Runbooks and handoff

**Do**
- Pick one workflow (example: “employee asks leave policy”)
- Write:
  - current pain
  - success metric
  - day-1 / week-1 / month-1 plan
- Draw a simple architecture on paper

**Done when**
- You can turn a vague customer request into a 1-week delivery plan

## Week 3 — AI FDE depth (if role is AI-related)

**Learn**
- Agent vs chatbot
- Tool calling
- RAG vs keyword search vs vector DB
- Guardrails
- Evaluation

**Do**
- Explain your HR Chat Agent (or similar project) using FDE language:
  - customer problem
  - constraints
  - what you shipped
  - how you measured success
  - what you would productize next

**Done when**
- You can defend architecture choices in plain English

## Week 4 — Interview / presentation polish

**Learn**
- Common FDE interview questions
- Security and compliance talking points
- Failure stories and recovery stories

**Do**
- Mock interview (record yourself)
- Prepare 3 stories:
  1. shipped under ambiguity
  2. handled a security/data constraint
  3. cut scope and still delivered value
- Update a one-page personal FDE summary

**Done when**
- You can answer practice questions without freezing

## Daily habit (30–45 minutes)

1. Read one short section
2. Speak one answer out loud
3. Write 5 lines of notes in your own words

## Weekly checklist

- [ ] Explained FDE to a friend in plain English
- [ ] Wrote one customer-style problem → solution plan
- [ ] Reviewed glossary terms you still mix up
- [ ] Practiced one technical deep-dive answer
